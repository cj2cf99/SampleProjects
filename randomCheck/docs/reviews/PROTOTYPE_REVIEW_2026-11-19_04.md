# 末骰临界翻倒复核

2026-11-19（JST） · 待用户确认

## 需求与比较基线

用户明确「你最后的那个吓人滚动应该表现为滚到分界线上几乎滚不动或者刚好滚过去才对。不是滚结束了再动一下。」上一轮 `PROTOTYPE_REVIEW_2026-11-19_03.md` 记录了原有末骰暂停后单独触发动作的方案及文件哈希。本次对照临界前持续减速、翻过或退回、全停后揭晓的要求。参考全局框架偏好的轻量实现，继续复用两种渲染器及已有骰子模型和结果。

## 发现与修正

| 发现 | 修正 |
| --- | --- |
| 上版主体停下后经过固定停顿，再启动额外动作 | 把末骰的翻倒轨迹接在最后一次落地上，与主体减速重叠。末段持续有角度变化，退回分支只在换向的一刻角速度为零 |
| 上版用固定角度近似是否翻过去，难以看出为什么会倒回 | 2D 从骰面轮廓、3D 从 Blender 网格投影取支撑边角，以支撑点到重心的竖直对齐作为临界点。翻过保留很小的速度过线，退回到临界角约 94.4% 时反向 |
| 接触与退回需要一致的重心移动 | 末段围绕同一接触点计算横向位置，接触阴影靠近支撑点并平滑恢复。给最后一枚骰预留边缘空间 |

## 实际检查

- `node --check` 检查 `motion.js` 通过。用临时 Node VM 脚本覆盖 D3–D8 的全部计分面、左右方向、2D/3D、两种结局和普通/减少动态效果，共 528 条轨迹。验证翻过时临界点前后位于不同侧，越线时速度很小且非零。验证退回接近临界点后反向，落定位置、角度和点数准确。
- 对 3–30 间的骰组及其末骰结果采样屏幕轮廓。进入临界阶段后最小横向余量约为画布宽度的 1.8%。
- 用隔离 Chrome 以同一结果录制两种收尾，并目检靠近、减速、临界附近、分支动作和落定的分帧图。两次均为 `4 + 7 + 8 + 3 = 22`。检查 390/320 像素宽度、减少动态效果、单骰、四骰及上下限结果。临时浏览器测试脚本已清理。
- 本轮通过本地复核。实体手机、跨浏览器实测和用户的观感确认尚未进行。
