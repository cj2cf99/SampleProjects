## 需求依据与范围

最初需求是做一个简单的掷骰页面，默认六面，可指定面数和数量，动画滚动后停在点数上，归入 `randomCheck`。后续明确以范围取代手动选骰，页面只需输入最小值和最大值。用户要求由网页随机数驱动，由 3–20 面骰组合完成 3–100 之间的任意整数范围，最多 6 枚，并提供 2D、3D 各一组动效和至少三轮画面精修。用户允许使用 Blender。

本次交付为可直接在浏览器打开的本地交互预览。按 3–100 内的闭区间实现，相同上下限允许投掷并显示该固定值。这一范围内 1–2 枚骰足以覆盖全部情况。两个画面共享同一次抽样，均停在实际参与换算的点数。3D 使用 Blender 生成的倒角模型，由网页实时绘制与翻转。较少动态效果下保留缩短的滚动过渡。

参考了 `G:/selftool/resourceforlater/docs/FRAMEWORK_PREFERENCES.md` 及 `C:/Users/asura/.claude/CLAUDE.md`。项目目录此前不存在，未发现项目设计备忘录。方案沿用轻量原生前端和紧凑布局。对比页首屏使用两个画面共需的模型文件，浏览器按输入范围准备实际使用的几何数据，空闲时停止重绘。

## 实测

- `G:/blender/app/blender.exe -b --factory-startup --python-exit-code 1 -P G:/samplePj/randomCheck/build_dice.py` 成功导出 d3–d20 共 18 个模型。每个模型的计分面完整覆盖该骰的全部点数。
- `node --check` 检查 `dice-meshes.js`、`motion.js`、`roll.js`，均通过。
- 用 Node VM 注入可控的浏览器随机字，穷举 4,851 个有效闭区间及 165,334 个组合索引。核对了选择的骰子面数和数量、点数与结果的映射、超额索引重抽、每个可取整数对应的组合数相同。反序、越界、空值及小数样例均拒绝。
- 使用临时 Chrome DevTools 驱动脚本对初版及三轮精修截图、检查。最终版在桌面尺寸和 390、320 像素宽度实测，经网页随机数投掷了单值、双值、奇数宽度、质数宽度和 d20 区间。结果均落在区间内，两个画面显示相同点数。最终截图在本次预览产物目录中以 `randomCheck-` 开头。
- 本地浏览器文件预览无需服务器，浏览器连接用于本机测试。未执行跨浏览器及实体手机测试。项目中的临时浏览器配置和 Chrome 驱动脚本已清理。
