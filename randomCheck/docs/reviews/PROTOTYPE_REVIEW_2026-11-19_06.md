# 骰子散落位置复核

2026-11-19（JST） · 待用户确认

用户原话「没必要非要拍成一排且保持顺序」。对照上一版 `PROTOTYPE_REVIEW_2026-11-19_05.md` 及既有加法、点数范围、末骰临界滚动设计。本轮仅修改落点分布和衔接。参考全局框架偏好中的最简实现，采用少量事先校验的错落布局，每轮随机选布局并洗牌骰子与落点的对应关系。两组画面使用同一次分配，骰面颜色及合计沿用原规则。连续掷骰的起点取上一轮落点，末骰仍在当前落点完成临界滚动。

## 复核结果

- 第一轮发现一组四骰布局在停稳后可能有明显边界重叠，拉开了几组落点的前后距离。
- 第二轮发现手机视口的四骰边界仍可能轻微相交。进一步加大后方留距，并微调四骰的大小。
- 第三轮复测桌面与小屏尺寸。对 1–4 枚骰的所有落点、适用骰面和两个末骰方向进行验证。采样 176,592 个末段姿态，最小画布余量约 12.4 像素。保守的停稳外接矩形无重叠。
- `node --check` 验证 `motion.js` 和 `roll.js`。隔离 Chrome 连续投掷同一组点数，两轮都得到 `4 + 7 + 8 + 3 = 22`，左右顺序及前后位置不同。检查 1440、390、320 像素宽度、两组点数一致、两种收尾和减少动态效果。临时验证脚本已清理。
- 本轮本地复核通过。实体手机、跨浏览器和用户观感确认待进行。
