# 手机优先的单骰台复核

2026-11-19（JST） · 待用户确认

用户原话「修改UI，只显示一种，可以选择，需要优先考虑手机怎么显示」。以 `PROTOTYPE_REVIEW_2026-11-19_08.md` 的镜面骰版本及 `_07.md` 的卡通骰、落点及界面记录为基线。参考全局框架偏好的紧凑、首屏必要内容和轻量原生实现。本轮采用默认 2D 卡通骰、可切换 3D 镜面骰的单骰台布局。

## 复核轮次

| 轮次 | 发现与处理 |
| --- | --- |
| 第一轮 | 将双骰台改为一个画布，在上方加入原生单选组。切换与同一次投掷共用当前帧、位置和结果。Chrome 验证触控、键盘切换和 320×568 同屏读点后，发现触碰遮罩偏重，小屏底部余量偏少 |
| 第二轮 | 去掉切换控件的系统蓝色触控遮罩，保留选中样式和键盘焦点。微调骰台高度及桌面最大宽度。复测发现 960×810 的结果卡底部仍超出首屏约 7 像素 |
| 第三轮 | 收紧桌面标题和设置区间距。复测全部九组视口，结果卡均在首屏，未发现剩余问题 |

## 实际验证

- `node --check` 检查 `motion.js` 和 `roll.js`。页面只挂载一个可见画布，绘制当前选择的样式。共享落点计算使用约 21 KB 的 D3–D8 几何资源。
- 隔离 Chrome 使用键盘方向键和触控事件切换样式。开始投掷后切换到 3D，同一轮按原节奏得到 `4 + 7 + 8 + 3 = 22`，停稳后切回 2D 时点数与结果一致。复测减少动态效果和输入错误提示，切换保持可用。
- 实测 320×568、360×640、390×844、430×932、600×800、760×820、761×820、960×810、1440×850。全部无横向溢出，模式选项触控区至少 44 像素。320×568 中结果卡底为 560 像素，390×844 中为 673 像素。保存单骰台截图，临时验证脚本已清理。
- 本地复核通过。实体手机、跨浏览器和用户实际观感待确认。
