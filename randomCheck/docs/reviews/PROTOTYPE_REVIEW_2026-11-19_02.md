## 需求与基线

用户反馈「缺少急速旋转到慢慢停下的物理效果，是个急停，而且缺少弹动的物理效果」，随后明确「骰子最大到D8」。对照上一版 `PROTOTYPE_REVIEW_2026-11-19.md`，继续保留仅输入最小值和最大值、覆盖 3–100 闭区间、网页随机抽样、两组动画展示同一结果。沿用全局框架偏好的紧凑、原生前端设计。项目没有 Git 基线，上一版与本版按两份记录的文件 SHA-256 比较。

## 修正与复核

| 轮次 | 发现 | 修正与复核结果 |
| --- | --- | --- |
| 1 | 原来的角速度曲线较短，落地位置按骰子中心估算，转动时边角与台面分离 | 加入短蓄力、高速旋转、三次逐渐减小的重力回弹和末段角速度衰减。2D 按旋转后轮廓计算支撑点，3D 按投影网格计算支撑点。独立调整每枚骰的起跳时间 |
| 2 | Chrome 起跳帧中的两枚平面骰轮廓重叠，3D D4 落定时支撑面表达不清 | 分开三骰的水平轨迹。为每个 3D 结果面计算贴合台面的支撑面，停下时仍能正向读点。复看起跳、触地、回弹、慢滚、落定截图，三骰轮廓和支撑符合本次要求 |
| 3 | 按原始需求和两项修订复查 | D3–D8 用 1–3 枚骰覆盖所有允许范围，独立检验区间映射和两画面点数一致。桌面和窄屏检查通过，未发现残留阻断项 |

- Blender 后台执行 `build_dice.py`，成功重新导出六个 D3–D8 网格。检查每个计分面齐全、各结果面的落定姿态有支撑面，以及数字朝向和可读方向。
- Node `--check` 检查 `motion.js`、`roll.js`、`dice-meshes.js`，均通过。
- 用 Node VM 注入可控随机字，穷举 4,851 个闭区间和 168,513 个组合索引。核对选骰、组合重抽、点数解码及每个结果的等概率映射。
- 采样两种动效的角速度和离地高度。2D 的旋转分量从约 6.14 转/秒降到临停约 0.002 转/秒，3D 从约 7.65 转/秒降到临停约 0.002 转/秒。三个回弹峰值逐次降低，落定时升高量和摇摆量归零。
- Chrome 本地检查真实点击、连掷、1/2/3 枚组合、无效输入和缩短动效。390×844 中两画面及结果在首屏，320 像素宽无横向溢出。保存约 3 秒的 MP4 和分段截图，临时浏览器测试脚本已清理。
- 本轮使用 Chrome 桌面及设备尺寸模拟。跨浏览器、实体手机和用户对动效的主观确认尚未进行。
